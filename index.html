Why your AI misreads your spreadsheet

When you paste a real business spreadsheet into an LLM — the kind with a title row, a units line, a three-level merged header, and category columns merged down five rows — three things go wrong:

Merged cells become holes

The anchor value survives; every covered cell turns blank. The model sees a table full of gaps and starts guessing.

Multi-level headers collapse

“本月发生 / 金额” and “本月发生 / 笔数” become two identical columns named after whichever fragment survived the paste.

Empty means something

A blank cell in a weekly-updated column isn’t missing data — it means “not updated yet”. Generic converters can’t tell your AI that.

tablefmt rebuilds the structure first — detects header depth, expands merges, maps the hierarchy — then emits markdown with hierarchy paths (/-separated) and empty-value annotations. Your original file is never touched.

FAQ

Is my file uploaded anywhere?

No. Parsing, restructuring and export all happen inside your browser using JavaScript. There is no server component in this tool at all.

Does it modify my original file?

Never. The output is markdown text (and an optional flattened .xlsx you explicitly download). Your original file stays exactly as it is — which matters when the file came from someone else.

How is this different from a normal Excel-to-markdown converter?

Generic converters dump cells — merged anchors survive, covered cells become holes, and multi-level headers turn into repeated fragments. tablefmt reads the merge ranges, reconstructs the hierarchy, resolves empty-value semantics, and annotates columns that look like periodic-summary fields.

Does it use AI?

No — and that’s the point. Deterministic rules mean the same file always produces the same output, offline, with zero token cost. The AI is on the other side of the paste: your ChatGPT or Claude reads the clean markdown.
